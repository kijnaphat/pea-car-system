# ลานรถ Digital Twin

เปิด `/dashboard` เพื่อใช้มุมมองลานรถ 3D ส่วนกราฟและรายงานเดิมอยู่ที่ปุ่ม **สถิติและรายงานเดิม**

## ข้อมูลจริง

- ใช้ `cars` และ `trip_logs` เดิม ไม่สร้างเที่ยวรถจากแอนิเมชัน
- สถานะปัจจุบันอ่าน `/api/fleet` ที่มี shared cache ทุก 60 วินาที หยุดอ่านเมื่อแท็บถูกซ่อน
- ไม่เปิด Realtime subscription แบบรายผู้ชม เพื่อรักษาการลด Log Ingestion เดิม การเปลี่ยนสถานะจึงมีความหน่วงตามรอบอ่าน/แคช
- รถพร้อมใช้/กำลังชาร์จ/ซ่อมแสดงในผังจำลอง รถออกภารกิจแสดงช่องประจำว่าง ไม่ใช่หลักฐานว่ารถอยู่สำนักงานจริง
- ช่องประจำอยู่ใน `fleet_parking_slots` ไม่เปลี่ยนตามการเรียงรายการ กรองรถ หรือรีเฟรชรถที่กำลังออก
- รถใหม่ที่แสดงในระบบได้รับเลขช่องถัดไปจาก trigger ไม่ใช้ช่องของคันเดิมซ้ำ
- Dashboard แสดงรายละเอียดและรายงานเท่านั้น ไม่มีลิงก์เปิดรายการรถ/เบิก/คืน/ชาร์จ ให้สแกน QR ที่รถเพื่อเข้าสู่ขั้นตอนเดิม (ไม่เปลี่ยนการตรวจสิทธิ์หรือ URL ของระบบเดิม)
- แบตเตอรี่เป็นค่าที่บันทึกพร้อมเวลาบันทึก ไม่ใช่ telemetry; ไม่มีความเร็ว น้ำมันคงเหลือ หรือระยะทางคงเหลือจำลอง

## การเคลื่อนไหว

เมื่อ snapshot เปลี่ยนจากพร้อมใช้เป็นเที่ยวขับ รถจำลองรอคิวถนนร่วมแล้ววิ่งออก เมื่อเที่ยวขับจบวิ่งกลับช่องเดิม ตัวจัดคิวภาพจำลองสงวนเวลา/พื้นที่ให้แต่ละเส้นทาง ตรวจกรอบตัวรถที่หมุนตามทาง และเลื่อนเวลาเริ่มเมื่อมีรถตัดกัน ปล่อยรถห่างอย่างน้อย 2.5 วินาที ใช้ความเร็วตามระยะทาง 2.3 หน่วยฉาก/วินาที (ไม่ใช่ความเร็วจริง) แยกเลนออก/เข้าและโค้งเลี้ยว คิวของรถคันเดียวรักษาลำดับเบิก–คืน ไม่มีการแก้สถานะธุรกิจเพราะแอนิเมชันรอคิว

รถรอออกยังอยู่ช่องเดิม รถรอคืนรอนอกทางเข้า มีข้อความ “คิวภาพจำลอง” บอกจำนวนที่วิ่ง/รอในฉากเท่านั้น การลดการเคลื่อนไหวและการเลื่อนย้อนหลังข้ามคิวได้ ป้ายลานจอดโซนถูกนำออก แต่ช่องประจำ Pxx, ข้อมูลรถ, อาคาร และจำนวนรถจริงยังเหมือนเดิม

โหลดหน้าใหม่ใช้สถานะฐานข้อมูลเป็นจุดตั้งต้น ไม่เล่นเหตุการณ์เก่า รถที่ออกไปแล้วไม่ปรากฏในช่องเดิม การชาร์จระหว่างเที่ยวขับไม่สร้างการเบิกรถครั้งใหม่

## ย้อนหลัง

เลือกวันตามเวลาไทย อ่านเฉพาะเที่ยวที่ทับกับวันนั้น กดเล่นที่ 1–120× หรือเลื่อนเวลาเอง การเลื่อนรีเซ็ตคิวภาพจำลองและสร้างภาพ ณ เวลานั้นโดยตรง

เป็นการย้อน **เที่ยวขับ/ชาร์จของรถที่ยังอยู่ใน fleet ปัจจุบัน** ไม่ใช่ประวัติสถานะซ่อม/การเพิ่มลบรถย้อนหลัง ข้อมูลเหล่านั้นยังอ่านจากรายงานเดิม

## สาธิต / การเข้าถึง

สาธิต 25 คันเป็นข้อมูลในหน่วยความจำ ปุ่มเบิก/คืน/ส่ง 3 คัน/คืนทั้งหมด/รีเซ็ตไม่ติดต่อ Supabase หรือส่ง Discord ข้อมูลจริงโหลดกลับเมื่อสลับไปสถานะปัจจุบัน

เลือกจากรถ 3D, ช่องว่าง หรือรายการปุ่มด้านข้าง ใช้คีย์บอร์ดเลือกจากรายการได้ มี 2D top-down, 2D grid สำรอง, zoom/pan/reset และ reduced-motion กล้อง isometric ใช้ orthographic; ฉากเป็น geometry จริง ไม่ใช่ภาพพื้นหลัง

โมเดลจำแนกตาม `car_type`: กระเช้า/เครน/ขุดเจาะมีอุปกรณ์ชัดเจน, บรรทุกใหญ่มี 6 ล้อ, บรรทุกเล็ก/มีหลังคา/กระบะ/ตู้/EV มีรูปทรงต่างกัน ประเภทใหม่ที่ไม่รู้จักใช้โมเดลกลาง ไม่เดาตามยี่ห้อ สีเป็นสีจำแนกในผังจำลอง ไม่ใช่สีตัวรถจริง และคงสีเดิมเมื่อสถานะเปลี่ยน/ถูกเลือก มี silhouette เดียวกันในรายการและผังสำรอง

ผังหลักเพิ่มความสูงและความกว้าง มีปุ่มขยายเต็มความกว้างเพื่อซ่อนรายการด้านข้างชั่วคราว กดอีกครั้งคืนขนาดและรายการเดิม มือถือคง panel รายละเอียดใต้ผังเพื่อไม่บังการเลือก

## ตรวจสอบ

ทดสอบ UI: อ่าน fleet จริง, filter/search/select/link, ย้อนหลังและเลื่อนเวลา, สาธิตหลายคันออก/กลับ, เข้า analytics เดิม และมือถือ โดยไม่สร้างธุรกรรมรถจริงระหว่าง QA
## ผังสำนักงานตามภาพ Eo.jpg

ผัง 3D อิงรูปที่ผู้ใช้ส่งและยืนยันให้เรียงช่องตามเลขประจำ: P01–P18 แถวบน,
P19–P30 แถวล่าง เริ่มตรงกับ P07 และสิ้นสุดตรงกับ P18 ด้านบน ช่องไม่มีรถ
(เช่น P29 ที่คันเดิมถูกลบ) แสดงว่าง ไม่สร้างรถหรือย้ายเลขของคันอื่น

สำนักงาน 4 ชั้นอยู่ข้างถนนทางเข้าเฉียงฝั่งซ้าย มีอาคาร 2 ชั้นใกล้ทางเข้า,
อาคาร 1 ชั้นกับโรงรถสองหลังใต้ถนน, โรงรถลูกค้าเหนือถนน, อาคาร 2 ชั้นด้านขวา,
แนวต้นไม้, ทางออกที่แยกขึ้นด้านขวา และทางตันหลังทางออก รูปร่างพื้นที่ตามผัง
แทนสี่เหลี่ยมเดิม โดยใช้ geometry แสง เงา และสีโมเดลรถชุดเดิม ไม่ใช้ภาพพื้นหลัง
หรือ texture ภายนอก สัดส่วนเป็นภาพจำลอง ไม่ใช่การสำรวจสถานที่จริง

รถออกจากช่องเข้าถนนกลางแล้วเลี้ยวออกด้านขวา รถคืนเข้าจากทางซ้ายแล้วกลับช่องเดิม
ตัวจัดคิวสงวนเวลา/พื้นที่บนเส้นทางใหม่ร่วมกัน รถที่รอออกยังอยู่ช่อง และรถที่รอเข้า
รอนอกสำนักงาน ทดสอบรถออกพร้อมกันทั้ง 30 ช่องและรถเข้า–ออกผสม ไม่เปลี่ยนธุรกรรม
หรือส่ง Discord จากการขยับโมเดล ช่องประจำใหม่เกิน P30 เพิ่มแถวและทางวิ่งด้านหลัง
โดยไม่วิ่งผ่านรถแถวหน้า

ตำแหน่งช่อง กล้อง ป้าย ถนน และเส้นทางใช้ module `fleetSiteLayout.js` ร่วมกัน
เลขช่องในฐานข้อมูลและวิธีอ่าน `/api/fleet` ทุก 60 วินาทีไม่เปลี่ยน ไม่เพิ่ม Realtime,
GPS, คำขอฐานข้อมูล หรือ Log Ingestion จากฉากนี้ Dashboard ยังคงดูรายละเอียด/
รายงานอย่างเดียว การเบิก–คืน–ชาร์จใช้ QR Code ที่รถเหมือนเดิม

### ระยะอาคารและการขยายช่องจอด

ตึกแดงกับสำนักงานถอยออกจากถนนเฉียง มีช่องว่างสำหรับทางเดิน รวมส่วนยื่นของ
กันสาดสำนักงานด้วย ถนนหน้าทางเข้าย้ายออกไปก่อนกลุ่มอาคาร ไม่พาดผ่านตึกแดง
ตำแหน่งอาคารและป้ายใช้ข้อมูลชุดเดียวกัน มี regression test ตรวจระยะจากขอบถนน

เมื่อได้รับเลขช่องใหม่ P31 จะสร้างแถว P31–P42 ทั้งแถว, P43 สร้าง P43–P54
และเพิ่มทีละ 12 ช่องต่อไป แถวใหม่มีทางวิ่งด้านหลังเว้นจากตัวรถและขยายพื้นกับ
กรอบกล้องตามไปเอง P01–P30 ไม่ย้าย และช่องของรถที่ลบไม่ถูกนำกลับมาใช้ใหม่
เป็นการขยายผังจำลองเท่านั้น ไม่ได้เพิ่มความจุลานจอดจริง หรือลงทะเบียนรถให้เอง
ทดสอบรถจากแถวใหม่ออก–กลับท่ามกลางรถจอดนิ่ง โดยไม่เพิ่มรถทดสอบในฐานข้อมูลจริง

### ถนนต่อเนื่องและโรงรถชาร์จ EV

ถนนทางเข้าใช้แนวโค้งเดียวกับถนนกลาง รวมผิวถนนและทางแยกเป็น polygon ชุดเดียว
ขอบถนนแสดงเฉพาะขอบนอก ไม่มีเส้นจากถนนอีกชิ้นมาตัดกลางทางแยก เส้นประตาม
ระยะบนแนวโค้ง เว้นทางแยกและทางม้าลาย ขยับโรงรถลูกค้าและทางออกให้พ้นแนวโค้ง/
ช่องจอด เพิ่มไฟถนนโซลาร์ แปลงต้นไม้ ม้านั่ง และทางเดิน เป็น geometry ไม่โหลด texture

โรงรถด้านล่างเป็นสถานีชาร์จจำลอง มี 4 ช่อง EV01–EV04 ตู้ สาย ไฟสถานะ หลังคา
โปร่งและแผงโซลาร์ รถที่สถานะ `charging` จอดใต้โรงรถนี้ ไม่ใช่ช่องประจำ Pxx
การเปลี่ยนเข้าสถานะชาร์จสร้างคิว `charge` ขับจากช่องเดิมเข้าโรงรถ; จบชาร์จสร้าง
`uncharge` กลับช่องเดิม ไม่แก้เลขช่อง สถานะฐานข้อมูล หรือรายการเบิก–คืน
เมื่อเปิดหน้าใหม่ รถที่ชาร์จอยู่ปรากฏที่สถานีทันที ไม่เล่นแอนิเมชันรายการเก่า

ช่อง EV จัดให้รถไฟฟ้าทั้ง fleet ตามเลขช่องประจำ ไม่เลื่อนตามจำนวนที่ชาร์จพร้อมกัน
หากเกิน 4 คัน เพิ่มแถวโรงรถ/จุดชาร์จและทางเข้าด้านข้าง พร้อมขยายพื้น/กล้อง
เส้นทางไม่ผ่านรถแถวหน้า มี tests ตรวจทั้งรถกำลังวิ่ง รอคิว และรถจอดนิ่ง
การชาร์จระหว่างเที่ยวขับยังคงเป็นรถออกภารกิจ ไม่ทำให้รถกลับสำนักงานใหญ่หรือ
ปิดงานหลอก ๆ พิกัดชาร์จในแผนผังคือภาพจำลอง ไม่ใช่การยืนยันสถานีชาร์จจริง

โหมดสาธิตเพิ่มปุ่มเริ่ม–จบชาร์จ (เฉพาะ EV) สำหรับลองการเคลื่อนที่ในหน่วยความจำ
โหมดจริงยังบันทึกชาร์จผ่าน QR ที่รถเหมือนเดิม; ไม่เพิ่ม polling, telemetry หรือ Discord
